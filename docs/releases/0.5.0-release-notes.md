# Localize Anything 0.5.0（发布说明草案）

> Draft only. This document does not create a tag, publish a package, or create
> a GitHub Release.

## 新定位

`0.5.0` 是首个 agent-native core 版本。Localize Anything 是面向 Codex、Claude
Code 等 Coding Agent 的本地化专业能力层，不是 Provider 平台、TMS、Workbench 或
项目构建系统替代品。

## 五命令核心

默认路径固定为：

```text
localize scan
→ localize glossary bootstrap
→ Coding Agent + 项目原生 build/test
→ localize check
→ localize review
→ human confirmation
→ localize report
```

核心能力包括：

- Project Memory：保存范围、locale、保留规则和已确认的项目语言决策；
- concept-centered Glossary：一个以产品概念为中心的 canonical Glossary；
- deterministic check：检查 key、placeholder、markup、escape、结构和锁定术语；
- independent review：为新的 Agent context 生成 review packet，隔离生成理由；
- finding/confirmation gate：人工确认只能关联开放 finding；
- readiness/report：按 blocking、actionable warning、coverage limitation、
  known/expected 和 informational 分类，输出精简 JSON/Markdown 报告。

## Standard 和 Release

- **Standard**：范围、Glossary、Coding Agent 实施、确定性检查、独立 Review 和
  高风险确认。
- **Release**：Standard 加页面截图、页面级 Review、项目原生 build/test、locale
  switch/persistence/detection/fallback、干净 Git diff 和发布证据。

## 格式支持

核心路径覆盖 JSON、YAML/TOML、Android XML、Apple `.strings` / `.xcstrings`、
PO/POT 和 XLIFF。Markdown/HTML、CSV/TSV/XLSX、Word、SRT/WebVTT、Wesnoth 的五个
兼容 Adapter 方向属于受限能力：必须显式调用，不自动 fallback，只保证 manifest
声明的机械检查或重建范围。

## 真实验证

- clean install、五命令最小 E2E、56 项仓库测试、compileall、协议和 Adapter
  validator 已通过；
- 在真实 Documenso checkout 中完成俄语签署完成页、认领表单和分享对话框验收；
- 通过 locale switch、cookie persistence、`Accept-Language` detection、source
  fallback、独立 review 和人工确认门验证；
- Documenso 的 `google.ts` Google Vertex 类型错误在干净 baseline 中同样存在，
  属于目标项目既有问题，不是 Localize Anything 缺陷。

## Breaking changes

- `localize-anything` 旧平台 CLI 已移除；`localize` 是唯一公开 CLI；
- Provider、Workbench、workflow、readiness、signoff、Knowledge Pack 和旧协议
  平台入口已移除；
- 旧状态文件不会被新核心自动读取；状态统一写入目标项目 `.localize-anything/`；
- 缺少格式支持时不会自动 fallback 到旧 Runtime；应由 Coding Agent 使用项目原生
  工具处理并记录 limitation；
- 旧脚本、CI 或 Skill 引用需要迁移到五个新命令。

## Known limitations

- 完整语义翻译仍由 Coding Agent 和人工判断完成；deterministic check 不证明自然度；
- 五个兼容 Adapter 不是完整平台支持，也不自动加载；
- 当前 protocol/Adapter manifest 是轻量契约，不是扩展插件市场；
- 报告的 `ready` 只针对声明范围，不能替代项目原生 build/test、截图或 Git review；
- 真实 Documenso 受控范围外的 catalog coverage 仍需另行声明和翻译；
- package manager、项目依赖或目标应用自身的构建错误必须由目标项目负责。

## 升级建议

1. 阅读[迁移说明](../migration/agent-native-core-migration.md)。
2. 确认脚本和 CI 不再调用旧平台入口。
3. 在目标项目中运行 `localize scan`，检查 `.localize-anything/` 和范围声明。
4. 按五命令路径完成一次小范围任务，再扩大覆盖。
